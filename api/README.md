# Movie Tracker API

The Symfony backend for [`../my-app`](../my-app). It handles accounts, each user's watched list, and a TMDB proxy that keeps the TMDB key on the server.

Built with **Symfony 8.1** (PHP 8.5), **Doctrine ORM** on **PostgreSQL 17**, and served by **FrankenPHP** in Docker.

## Run

```bash
echo "TMDB_TOKEN=<your key>" > .env.local     # git-ignored
docker compose up -d --build                  # php on http://localhost:8000 + database
docker compose exec php bin/console doctrine:migrations:migrate -n
```

`TMDB_TOKEN` can be a TMDB v3 API key or a v4 read access token.

Everyday commands run inside the container:

```bash
docker compose exec php bin/console debug:router   # list routes
docker compose exec php bin/phpunit                 # run the tests
docker compose logs -f php                          # server logs
```

The tests use a separate `app_test` database. Create it once with:

```bash
docker compose exec php sh -c 'bin/console doctrine:database:create --env=test && bin/console doctrine:migrations:migrate --env=test -n'
```

## Routes

Every route except `/api/auth/*` needs a logged-in session. Errors are always JSON: `{ "statusCode": 400, "message": "..." }`. Every `/api/watched` route answers with the whole updated list, newest first.

| Method   | Route                  | Description |
| -------- | ---------------------- | ----------- |
| `POST`   | `/api/auth/register`   | `{ username, password }` creates an account and logs in. Username: 3–30 of `a-z 0-9 _` (lowercased). Password: 8–200 characters. 409 if the username is taken. |
| `POST`   | `/api/auth/login`      | `{ username, password }`. Returns 401 "Invalid username or password" whichever one is wrong. |
| `POST`   | `/api/auth/logout`     | Ends the session (204) |
| `GET`    | `/api/auth/me`         | `{ user: { username } }`, or `{ user: null }` when signed out |
| `GET`    | `/api/movies?q=&page=` | TMDB popular movies, or search results when `q` is set. `page` 1–500. Cached 1 hour. |
| `GET`    | `/api/movies/{id}`     | TMDB details with credits and videos. Cached 1 day. |
| `GET`    | `/api/watched`         | The watched list |
| `POST`   | `/api/watched`         | `{ id, title, poster_path?, release_date? }` marks a movie as watched. Does nothing if it is already in the list. |
| `PATCH`  | `/api/watched/{id}`    | `{ rating: 1–5 \| null, review: string ≤ 1000 }`. Empty values clear the field. |
| `DELETE` | `/api/watched/{id}`    | Removes a movie |
| `POST`   | `/api/watched/bulk`    | `{ add: Movie[], remove: id[] }`, at most 500 items, in one transaction |

## How it is built

```
src/
  Controller/      AuthController, MovieController, WatchedController: thin, #[Route] + #[IsGranted]
  Dto/             request bodies and queries, bound with #[MapRequestPayload] / #[MapQueryString] and validated with #[Assert\...]
  Entity/          User, WatchedMovie (one row per movie, unique per user + TMDB id)
  Repository/      queries; UserRepository also loads users for login (case-insensitive)
  Service/         WatchList (watched-list logic), TmdbClient (TMDB calls + cache)
  Security/        AuthenticationFailureHandler: the 401 JSON on a bad login
  EventListener/   ApiExceptionListener (JSON errors), LogoutListener (204 instead of a redirect)
config/packages/
  security.yaml    json_login firewall, session-based, access_control for /api
  http_client.yaml the scoped tmdb.client
migrations/        database schema, generated by make:migration
tests/Controller/  functional tests for every route (TMDB is mocked)
```

- **Auth:** Symfony's `json_login` checks the password (hashed with the `auto` hasher) and stores the user in the PHP session. The session cookie is HttpOnly and SameSite=Lax, and request bodies are only accepted as JSON. Together these block cross-site form posts.
- **Database:** each watched movie is its own row, so concurrent requests can't overwrite each other's changes. Schema changes go through Doctrine migrations.

## Before production

- Store sessions in the database or Redis instead of files in `var/sessions`. This is needed as soon as there is more than one PHP container.
- Point the `cache.app` pool at Redis, for the same reason.
- Use a production FrankenPHP image (worker mode, `APP_ENV=prod`, `composer dump-env prod`) and real secrets via `bin/console secrets:set`.
- Add rate limiting on `/api/auth/login` (`login_throttling` in `security.yaml`, which needs `symfony/rate-limiter`).
